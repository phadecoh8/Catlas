CATLAS SUPABASE SETUP GUIDE

This guide is for the Supabase project used by the Catlas web app. It explains
where to find the project URL and API keys, how to configure Auth, and includes
the complete database SQL from schema.sql at the end of this file.

KEEP KEYS PRIVATE

- The publishable key starts with sb_publishable_. It is designed for app
  requests protected by Row Level Security (RLS).
- The secret key starts with sb_secret_. It bypasses RLS. Never put it in a
  NEXT_PUBLIC_ variable, browser code, source control, screenshots, or chat.
- This app's student sign-up and sign-in need the project URL and publishable
  key. The server-side waitlist routes also read SUPABASE_SECRET_KEY.
- AUTH_SECRET is an Auth.js cookie secret. It is not a Supabase key.

WHAT THIS PROJECT IS USED FOR

This Supabase project serves the web app: student accounts (Supabase Auth),
the signup dropdowns (schools, faculties, departments), student profiles, and
the waitlist. The Express API in apps/api uses its own separate Postgres
database configured with DATABASE_URL in apps/api/.env. Do not reuse this
project's keys there. The waitlist database documented in the AGENTS.md
approved stack is this project's waitlist_signups table.

1. CREATE OR OPEN THE PROJECT

Open https://supabase.com/dashboard and create a project for Catlas, or open
its existing Catlas project. Use this same project for the URL and keys below.

Before running the SQL, make sure this is the intended Catlas project. The SQL
creates a trigger named on_auth_user_created on auth.users. If that trigger
already exists and belongs to another application, stop and review it first;
the script replaces a trigger with that name.

2. GET THE PROJECT URL AND KEYS

In the project dashboard:

- Open Connect to copy the project URL and publishable key.
- To see or create API keys, open Project Settings, then API Keys.
- Copy the publishable key for NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY.
- Copy a secret key only for SUPABASE_SECRET_KEY. Keep it server-side.

The signup code uses the publishable key with RLS. The waitlist server routes
need the secret key to read and write waitlist data. Do not send either key in
chat. Use your local .env.local file as described in step 5.

3. RUN THE DATABASE SQL

In the project dashboard, open SQL Editor, choose New query, paste all of the
SQL found under FULL SQL SCRIPT below, and click Run. This creates the waitlist
table, schools, faculties, departments, student profiles, access policies and
a profile trigger. The trigger always creates student profiles with role
student; it does not take a role from signup form metadata. Student status is
reviewed by the school: email confirmation verifies the email address, not
student enrollment. Keep a signup pending and block student app access until
the school accepts it. Acceptance activates access and sends the student
automatically to the student home page. The schema and app need the school's
review status and decision fields/policies before this workflow can be used;
do not treat email confirmation alone as acceptance.

4. ADD THE DEMO SCHOOL AND FACULTIES

The full schema below seeds the demo options documented in README.md:
Federal University of Oye, Ikole Campus; Faculty of Engineering; and Faculty
of CIESA. It also seeds the four listed pilot departments so signup can be
used after the schema is applied. These values are the initial demo data; use
the statements below to add other schools, faculties, or departments later.

The signup page reads these rows from the Supabase tables and displays them
in its School, Faculty, and Department dropdowns. After you run the full SQL
script and configure the Supabase URL and publishable key in
apps/web/.env.local, open the registration page; the demo options will appear
there. The same rows will be visible under Table Editor for schools,
faculties, and departments.

Replace every placeholder with real information before running these
statements. Do not run them with the placeholder text unchanged.

First insert the school and copy the returned UUID:

insert into public.schools (name)
values ('REPLACE WITH THE REAL SCHOOL NAME')
returning id;

Use that school UUID to insert each faculty and copy each returned faculty ID:

insert into public.faculties (school_id, name)
values ('PASTE SCHOOL UUID', 'REPLACE WITH FACULTY NAME')
returning id;

Use both returned UUIDs to insert each department:

insert into public.departments (school_id, faculty_id, name)
values (
  'PASTE SCHOOL UUID',
  'PASTE FACULTY UUID',
  'REPLACE WITH DEPARTMENT NAME'
)
returning id;

Repeat the faculty and department inserts for each real campus option. Names
must match the school's actual organization. The code filters the lists using
the school_id and faculty_id relationships.

5. CONFIGURE THE WEB APP

Create or edit apps/web/.env.local. Use these variable names and your own
values; do not commit this file:

NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_VALUE
SUPABASE_SECRET_KEY=sb_secret_YOUR_VALUE
SITE_URL=http://localhost:3000
AUTH_SECRET=GENERATE_A_RANDOM_SECRET
AUTH_URL=

AUTH_URL is the Auth.js base URL. Leave it empty for local development and
set it to the production site URL when you publish if Auth.js asks for it.

Two legacy variable names are still read as fallbacks by some server routes
(apps/web/src/app/api/founder/waitlist/route.ts reads
NEXT_PUBLIC_SUPABASE_ANON_KEY, and several routes read
SUPABASE_SERVICE_ROLE_KEY). To be safe while that code is in place, set them
to the same values as their replacements:

NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_YOUR_VALUE
SUPABASE_SERVICE_ROLE_KEY=sb_secret_YOUR_VALUE

Never rename the secret key or service role key with a NEXT_PUBLIC_ prefix;
both must stay server-side only.

AUTH_SECRET can be generated locally with this command, then copied into the
environment file:

node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"

The student login/signup flow only needs NEXT_PUBLIC_SUPABASE_URL and
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY. SUPABASE_SECRET_KEY is used by server-only
waitlist routes. Never rename it to NEXT_PUBLIC_SUPABASE_SECRET_KEY.

6. CONFIGURE SUPABASE AUTH

In the dashboard, open Authentication > Sign In / Providers > Email:

- Allow new users to sign up.
- Enable email confirmation so users verify their email before signing in.

Then open Authentication > URL Configuration:

- Set Site URL to http://localhost:3000 for local development.
- Add http://localhost:3000/verify-email to the Redirect URLs allow list.
- Add http://localhost:3000/reset-password to the Redirect URLs allow list
  too. The password reset pages are not finished yet, so the link is unused
  today; adding it now avoids a broken reset flow after launch.

The signup route redirects confirmation emails to /verify-email. When you
publish the site, replace the local URLs with the production site URL and add
the production verification and reset URLs to the allow list.

Supabase's built-in email sender is for limited testing. It only sends to
project team email addresses and has a very low limit. To send confirmations
to other addresses, configure custom SMTP under Authentication
(Advanced > SMTP Settings in the project dashboard).

7. RESTART AND TRY SIGNUP

Restart the dev server after changing .env.local. Open http://localhost:3000/signup,
choose a school, faculty and department, and create an account with an email
you can access. Click the confirmation link, then wait for the school to
review and accept the enrollment request. Once accepted, the student is sent
automatically to their student home page. Check Authentication > Users for the
Auth user and Table Editor > profiles for the student profile and its school
review status.

If the school dropdown is empty, check the Network panel for
`/api/auth/schools`. A successful response should include a `schools` array.
If it returns an error, confirm that `NEXT_PUBLIC_SUPABASE_URL` and
`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` point to this same Supabase project,
restart the web dev server after changing `.env.local`, and run the full SQL
script above in that project's SQL Editor. The script seeds
Federal University of Oye, Ikole Campus and is safe to run again. In Table
Editor, confirm that `public.schools` contains that name and its `is_active`
value is `true`; also confirm the related faculty and department rows are
active. The public select grants and active-row policies at the end of the
script must be applied for all three dropdown tables.
If signup says it is not configured, restart the server after saving the env
file and check the two NEXT_PUBLIC_SUPABASE_* values.

FULL SQL SCRIPT

Copy everything between the SQL markers below into the Supabase SQL Editor.
This is the same script as apps/web/supabase/schema.sql.

----- BEGIN SQL -----

-- Run this script in the Supabase SQL Editor for the Catlas project.
create extension if not exists pgcrypto;

create table if not exists public.waitlist_signups (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  school text not null,
  faculty text not null,
  department text not null,
  level text not null,
  email text not null,
  consented_at timestamptz not null,
  created_at timestamptz not null default now()
);

create unique index if not exists waitlist_signups_email_unique
  on public.waitlist_signups (lower(email));

alter table public.waitlist_signups enable row level security;

revoke all on table public.waitlist_signups from public;
revoke all on table public.waitlist_signups from anon;
revoke all on table public.waitlist_signups from authenticated;

grant select, insert on table public.waitlist_signups to service_role;

-- Student accounts use Supabase Auth. Profiles contain only campus details;
-- passwords and verified email addresses remain in auth.users.
create table if not exists public.schools (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  is_active boolean not null default true,
  created_at timestamptz not null default now()
);

create unique index if not exists schools_name_unique
  on public.schools (lower(name));

create table if not exists public.faculties (
  id uuid primary key default gen_random_uuid(),
  school_id uuid not null references public.schools (id),
  name text not null,
  is_active boolean not null default true,
  created_at timestamptz not null default now(),
  unique (id, school_id)
);

create unique index if not exists faculties_school_name_unique
  on public.faculties (school_id, lower(name));

create table if not exists public.departments (
  id uuid primary key default gen_random_uuid(),
  school_id uuid not null references public.schools (id),
  faculty_id uuid not null,
  name text not null,
  is_active boolean not null default true,
  created_at timestamptz not null default now(),
  unique (id, school_id, faculty_id),
  foreign key (faculty_id, school_id)
    references public.faculties (id, school_id)
);

create unique index if not exists departments_faculty_name_unique
  on public.departments (faculty_id, lower(name));

-- Seed the demo school and pilot faculties from README.md.
insert into public.schools (name)
values ('Federal University of Oye, Ikole Campus')
on conflict (lower(name)) do nothing;

insert into public.faculties (school_id, name)
select school.id, faculty.name
from public.schools as school
cross join (
  values
    ('Faculty of Engineering'),
    ('Faculty of CIESA')
) as faculty(name)
where lower(school.name) = lower(
  'Federal University of Oye, Ikole Campus'
)
on conflict (school_id, lower(name)) do nothing;

insert into public.departments (school_id, faculty_id, name)
select school.id, faculty.id, department.name
from public.schools as school
join public.faculties as faculty
  on faculty.school_id = school.id
cross join (
  values
    ('Faculty of Engineering', 'Mechanical Engineering'),
    ('Faculty of Engineering', 'Material Engineering'),
    ('Faculty of CIESA', 'Mechatronics Engineering'),
    ('Faculty of CIESA', 'Computer Engineering')
) as department(faculty_name, name)
where lower(school.name) = lower(
  'Federal University of Oye, Ikole Campus'
)
  and lower(faculty.name) = lower(department.faculty_name)
on conflict (faculty_id, lower(name)) do nothing;

create table if not exists public.profiles (
  id uuid primary key references auth.users (id) on delete cascade,
  school_id uuid not null references public.schools (id),
  faculty_id uuid not null,
  department_id uuid not null,
  role text not null default 'student'
    check (role in (
      'student',
      'class_governor',
      'committee',
      'hod',
      'dean',
      'vc',
      'founder'
    )),
  surname text not null,
  first_name text not null,
  phone text not null,
  level smallint not null check (
    level between 100 and 800 and level % 100 = 0
  ),
  jamb_reg_no text,
  matric_no text,
  avatar_url text,
  consented_at timestamptz not null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  foreign key (faculty_id, school_id)
    references public.faculties (id, school_id),
  foreign key (department_id, school_id, faculty_id)
    references public.departments (id, school_id, faculty_id)
);

create unique index if not exists profiles_jamb_number_unique
  on public.profiles (school_id, lower(jamb_reg_no))
  where jamb_reg_no is not null;

create unique index if not exists profiles_matric_number_unique
  on public.profiles (school_id, lower(matric_no))
  where matric_no is not null;

create or replace function public.create_student_profile()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
declare
  selected_school_id uuid :=
    (new.raw_user_meta_data ->> 'school_id')::uuid;
  selected_faculty_id uuid :=
    (new.raw_user_meta_data ->> 'faculty_id')::uuid;
  selected_department_id uuid :=
    (new.raw_user_meta_data ->> 'department_id')::uuid;
begin
  if not exists (
    select 1
    from public.schools as school
    join public.faculties as faculty
      on faculty.school_id = school.id
    join public.departments as department
      on department.faculty_id = faculty.id
      and department.school_id = school.id
    where school.id = selected_school_id
      and faculty.id = selected_faculty_id
      and department.id = selected_department_id
      and school.is_active
      and faculty.is_active
      and department.is_active
  ) then
    raise exception 'The selected campus details are unavailable';
  end if;

  insert into public.profiles (
    id,
    school_id,
    faculty_id,
    department_id,
    role,
    surname,
    first_name,
    phone,
    level,
    jamb_reg_no,
    consented_at
  )
  values (
    new.id,
    selected_school_id,
    selected_faculty_id,
    selected_department_id,
    'student',
    trim(new.raw_user_meta_data ->> 'surname'),
    trim(new.raw_user_meta_data ->> 'first_name'),
    trim(new.raw_user_meta_data ->> 'phone'),
    (new.raw_user_meta_data ->> 'level')::smallint,
    nullif(trim(new.raw_user_meta_data ->> 'jamb_reg_no'), ''),
    now()
  );

  return new;
end;
$$;

drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function public.create_student_profile();

create or replace function public.touch_updated_at()
returns trigger
language plpgsql
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;

drop trigger if exists profiles_updated_at on public.profiles;
create trigger profiles_updated_at
  before update on public.profiles
  for each row execute function public.touch_updated_at();

alter table public.schools enable row level security;
alter table public.faculties enable row level security;
alter table public.departments enable row level security;
alter table public.profiles enable row level security;

drop policy if exists "Active schools are visible" on public.schools;
create policy "Active schools are visible"
  on public.schools for select to anon, authenticated
  using (is_active);

drop policy if exists "Active faculties are visible" on public.faculties;
create policy "Active faculties are visible"
  on public.faculties for select to anon, authenticated
  using (is_active);

drop policy if exists "Active departments are visible" on public.departments;
create policy "Active departments are visible"
  on public.departments for select to anon, authenticated
  using (is_active);

drop policy if exists "Users can read their own profile" on public.profiles;
create policy "Users can read their own profile"
  on public.profiles for select to authenticated
  using (id = (select auth.uid()));

drop policy if exists "Users can update their own student profile" on public.profiles;
create policy "Users can update their own student profile"
  on public.profiles for update to authenticated
  using (id = (select auth.uid()) and role = 'student')
  with check (id = (select auth.uid()) and role = 'student');

revoke all on public.schools from public, anon, authenticated;
revoke all on public.faculties from public, anon, authenticated;
revoke all on public.departments from public, anon, authenticated;
revoke all on public.profiles from public, anon, authenticated;

grant select on public.schools to anon, authenticated;
grant select on public.faculties to anon, authenticated;
grant select on public.departments to anon, authenticated;
grant select on public.profiles to authenticated;
grant update (surname, first_name, phone)
  on public.profiles to authenticated;

grant all on public.schools to service_role;
grant all on public.faculties to service_role;
grant all on public.departments to service_role;
grant all on public.profiles to service_role;

----- END SQL -----
